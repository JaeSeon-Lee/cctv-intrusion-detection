# CCTV 침입 감지 — 발표 요약

> 초안용 Markdown. 발표 시에는 이 내용을 슬라이드(PPT/Keynote)로 옮기거나  
> Marp / Slidev 등으로 그대로 투영해도 됩니다.

---

## 1. 목표

실제 CCTV 관제 환경을 최대한 비슷하게 구현하는 것.

- 여러 화면을 동시에 보며 위험구역을 감시
- 사람이 구역에 일정 시간 머물면 경보
- 상시 녹화 + 침입 구간 클립·로그 자동 저장
- 다시보기로 사건 확인

---

## 2. 지금까지의 수정 히스토리

| 단계 | 내용 |
|---|---|
| UI / 모니터 | CCTV 4분할, 다시보기 탭, 배속, 크게 보기 시 파일 오디오 |
| 시작 동작 | CAM1 웹캠 + CAM2~4 `data/cctv/camN.mp4` **자동 재생** |
| 위험구역 | 화면(슬롯)별 폴리곤·등급, 편집 중에도 재생 유지 |
| 침입 판정 | YOLO **발 위치** 기준 구역 교차 + 등급별 체류 → 경보 |
| 상시 녹화 | 오버레이 포함 MPEG-TS (`.ts`), 캠별 `recordings/camN/` |
| 침입 클립 | JPEG 버퍼 없이 **상시 `.ts`에서 구간 절단** → `live_*.mp4` + CSV |
| 다시보기 | 녹화 중 `.ts`는 스냅샷 재생, 녹화본은 오버레이 중복 표시 안 함 |
| 탐지 부하 | YOLO 1개 + **캠별 최신 프레임 큐** |

## 3. 파이프라인 (한 장)

```
영상(웹캠/파일)
  → 사람 탐지 (YOLO11s, 워커 1개·캠별 최신 큐)
  → 발 점 × 위험구역 폴리곤 + 등급별 체류
  → 경보 / 해제
  → 상시 .ts 녹화 (항상)
  → 침입 시 .ts에서 클립 절단 + events.csv
```

---

## 4. 상시 녹화 vs 침입 클립

| | 상시 녹화 | 침입 클립 |
|---|---|---|
| 형식 | `.ts` (MPEG-TS) | `live_*.mp4` |
| 언제 | 소스 연결 중 계속 | 경보 해제 후 **+5초** 지나면 저장 |
| 구간 | 세션 전체 | 경보 **−3초 ~ 해제 +5초** |
| 내용 | 구역·박스·상태 배지 포함 | 상시 파일에서 같은 구간을 잘라옴 |
| 재경보 | — | 해제 후 5초 안이면 **한 클립으로 연장** |

---

## 4-1. 침입 클립은 어떻게 따나? (초기 → 현재)

### 초기 방식: `LiveRecorder` (프레임 JPEG 버퍼)

```
매 프레임
  → JPEG 로 압축해 메모리 deque 에 보관 (경보 전 3초+여유)
  → 경보가 나면 VideoWriter 로 mp4 파일 열기
  → 버퍼에 있던 프레임을 디코드해서 파일에 쓰고
  → 이후 프레임도 계속 인코딩하며 씀
  → 해제 +5초 후 파일 닫기 + CSV
```

- 웹캠·파일 캠 모두 “지금 흘러가는 화면”처럼 취급하려고 만든 방식  
- **문제:** 4캠 × 매 프레임 JPEG 인코딩·복사 → UI 스레드 부하·렉  
- 상시 녹화(`.ts`)와 **같은 영상을 두 번** 만드는 셈

### 현재 방식: `IntrusionClipper` (상시 `.ts` 구간 절단)

```
평소
  → ContinuousRecorder 가 오버레이 프레임을 ffmpeg stdin 으로 .ts 에만 기록

경보 확정
  → “클립 구간 열림” 표시만 (프레임을 따로 안 모음)

경보 해제
  → stop_at = 해제시각 + 5초 예약
  → (5초 안에 다시 경보나면 stop_at 취소, 같은 클립으로 연장)

영상 시각 ≥ stop_at
  → ClipExportJob 1건 생성
  → 백그라운드 스레드에서:
       1) 녹화 중 .ts 스냅샷(복사/COW)
       2) ffmpeg 로 [경보−3초, 해제+5초] 구간 재인코딩 → live_*.mp4
       3) events.csv 에 한 줄(또는 연장분이면 여러 줄) 기록
```

### “침입되면 큐에 넣어서 mp4로 변환하나?”

| 구분 | 하는가? | 설명 |
|---|---|---|
| YOLO 캠별 최신 프레임 **큐** | ✅ | 탐지용. 클립과 무관 |
| 침입 시 프레임을 큐에 모아 mp4 변환 | ❌ (폐기) | 초기 JPEG 버퍼 방식이 이에 가까웠음 |
| 침입 종료 후 **작업 1건**을 백그라운드로 | ✅ (현재) | `ClipExportJob` → 스레드에서 `.ts`→구간 mp4 **한 번** |

즉 지금은 “침입 감지될 때마다 인코딩 큐에 프레임을 넣는다”가 아니라,  
**상시는 이미 `.ts`로 쓰고, 사건이 끝난 뒤에만 자르기 작업을 백그라운드로 한 번 돌린다.**

UI를 막지 않으려고 ffmpeg 절단은 `threading.Thread`로 돌린다.  
(영구 작업 큐 라이브러리라기보다, 캠당 “지금 export 중이면 재시도하지 않음” 플래그)

## 4-2. 클립 저장 시점 (타임라인)

1. 경보 확정 → 클립 구간 열림  
2. 경보 해제 → `stop_at = 해제시각 + 5초` 예약  
3. 영상 시각 ≥ `stop_at` → 백그라운드 스냅샷 → 절단 → CSV  

로그의 `클립 저장 시점 도달` = 3번이 실행된 순간.

## 5. 다시보기

- 좌측: 상시 `.ts` 목록 + 침입 `.mp4` 목록  
- 녹화 **중**인 `.ts`: OpenCV가 파일 끝을 못 따라가므로 **순간 스냅샷**으로 재생  
- 녹화본·클립: 이미 오버레이가 박혀 있어 UI에서 상태 배지를 **다시 그리지 않음** (중복 방지)

## 6. YOLO 4화면과 큐

### 상황

- 캠 4개를 동시에 재생·감시, 사람 위치는 YOLO
- 재생은 매 프레임, 추론은 프레임마다 시간이 걸림

### 선택: 캠별 최신 프레임 큐

- YOLO **1개** 유지  
- 캠마다 **가장 최근 1장**만 보관 → 돌아가며 추론  
- 중간 프레임은 버리고, 박스는 직전 결과 유지  

> 모든 프레임을 YOLO로 돌리는 것이 아니라,  
> **화면은 끊기지 않게 · 탐지는 사양이 되는 속도로 · 캠이 공평하게**.

## 7. 저장 위치·운영

```
data/recordings/cam1/ … cam4/
  ├── 20260929_003432.ts     # 상시
  ├── live_20260929_003445.mp4
  └── events.csv
```

- 위험구역: `data/cctv/screens/screen_N.json`  
- 데모 영상: `data/cctv/cam2.mp4` ~ `cam4.mp4`

**권장:** 앱을 종료한 뒤 다시 실행하기 전에  
`data/recordings/cam1` ~ `cam4` 폴더(또는 그 안의 파일)를 비우면  
디스크가 덜 차고, 다시보기·클립 테스트가 깔끔하다. (README에도 동일 안내)

## 8. 한 줄 정리

> 4분할 CCTV 관제 UX + 구역·경보 + 상시 `.ts` 녹화,  
> 침입 클립은 **초기 JPEG 버퍼 → 현재는 상시 `.ts` 절단(백그라운드 1회 작업)**,  
> 4영상 YOLO 부하는 **캠별 최신 프레임 큐**로 완화했다.
